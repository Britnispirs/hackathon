# Голосовой Ассистент Задач и Встреч

Прототип интеллектуального голосового ассистента для управления личным расписанием, встречами, задачами и напоминаниями на естественном русском языке.

- Репозиторий: [https://github.com/Britnispirs/hackathon.git](https://github.com/Britnispirs/hackathon.git)
- Веб-интерфейс: `http://localhost:8000`
- Swagger API Docs: `http://localhost:8000/docs`

---

## Основные возможности

1. **Создание задач и напоминаний**:
   - «Напомни мне завтра в 10 утра позвонить Ивану»
   - «В пятницу нужно отправить отчет»
   - «Поставь задачу купить билеты до конца недели»
   - «Через два часа проверить сервер»

2. **Создание встреч и уточняющий диалог**:
   - «Добавь встречу с командой завтра в 15:00»
   - «В четверг в 11 у меня встреча с дизайнером»
   - Уточнение недостающих данных: «Поставь встречу с Иваном завтра» → Ассистент: «На какое время поставить встречу?». При ответе пользователя («в 15:00») встреча сохраняется с указанным временем.

3. **Анализ конфликтов расписания**:
   - Проверка пересечений встреч по времени в реальном времени. При наложении ассистент предупреждает о конфликте голосом и в интерфейсе.

4. **Получение расписания и фильтрация**:
   - «Что у меня сегодня?»
   - «Есть ли у меня встречи сегодня?»
   - «Какие задачи у меня на завтра?»
   - «Что запланировано на эту неделю?»

5. **Гибридный семантический поиск по старым событиям**:
   - «Найди задачу про презентацию»
   - «Когда у меня была встреча с Иваном?»
   - «Я когда-то ставил задачу по договору, найди ее»
   - Поиск работает с близкими по смыслу формулировками благодаря стеммингу и смысловым кластерам синонимов (договор ↔ контракт ↔ соглашение ↔ акт, презентация ↔ слайды ↔ питч ↔ демо).

6. **Управление контекстом и действиями**:
   - Контекстный перенос: «А перенеси ее на завтра»
   - Отметка выполнения: «Отметь задачу про договор выполненной»
   - Удаление: «Удали задачу про презентацию»

7. **Двойной интерфейс**:
   - Режим **Списка** с разделением на активные дела и блок «Выполненные».
   - Интерактивный **Календарь** с навигацией по месяцам, цветовыми маркерами событий и просмотром планов по дням.
   - Экспорт расписания в формат `.ics` для Apple Calendar / Google Calendar.

Проект спроектирован с четким разделением ответственности компонентов:

```
├── backend/
│   ├── app/
│   │   ├── main.py              # Точка входа FastAPI, CORS, раздача статики
│   │   ├── database.py          # Инициализация SQLite3, индексы, FTS5
│   │   ├── seed.py              # Загрузка тестового набора данных (seed_events.csv)
│   │   ├── models/
│   │   │   └── event.py         # Pydantic v2 модели и схемы данных
│   │   ├── api/
│   │   │   ├── events.py        # REST CRUD, фильтры, поиск, экспорт iCal (.ics)
│   │   │   └── assistant.py     # Эндпоинты диалога (/api/assistant/chat, сброс сессии)
│   │   └── services/
│   │       ├── nlu_parser.py    # Извлечение намерений, дат, времени и участников
│   │       ├── dialog_manager.py# Управление контекстом, уточнения, конфликты
│   │       ├── search_service.py# Гибридный поиск (FTS5 + синонимы + стемминг)
│   │       └── llm_client.py    # LLM-адаптер (Groq / Llama) с fallback на NLU
│   ├── data/                    # База данных SQLite и seed_events.csv
│   └── requirements.txt
├── frontend/
│   ├── index.html               # Разметка интерфейса и модальных окон
│   ├── css/style.css            # Монохромные строгие стили без градиентов
│   └── js/
│       ├── speech.js            # Web Speech API (STT/TTS) + Web Audio API visualizer
│       └── app.js               # Клиентская логика, реактивность, календарь, чат
├── tests/
│   └── test_assistant.py        # Pytest сьют (NLU, диалог, поиск, конфликты)
├── Dockerfile
├── docker-compose.yml
└── .dockerignore
```

## Быстрый запуск

### Вариант 1. Через Docker Compose (рекомендуемый)

```bash
docker compose up -d --build
```

Приложение будет доступно по адресу: **`http://localhost:8000`**.

Для остановки:
```bash
docker compose down
```

---

### Вариант 2. Локальный запуск

1. Создайте и активируйте виртуальное окружение:
```bash
python3 -m venv venv
source venv/bin/activate
```

2. Установите зависимости:
```bash
pip install -r backend/requirements.txt
```

3. Запустите сервер:
```bash
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload
```

Откройте в браузере: `http://localhost:8000`.

## Запуск тестов

В проекте реализован набор автоматических тестов, покрывающий ключевые сценарии NLU, извлечение дат/времени, семантический поиск, уточняющие диалоги и выявление конфликтов:

```bash
pytest tests/ -v
```

---

## Принятые решения

1. **Автономный NLU с нулевой задержкой**:
   Встроен детерминированный русскоязычный парсер дат, времени, относительных интервалов и сущностей. Это гарантирует мгновенный ответ (0-5 мс), стабильность без внешних сетевых зависимостей и бесплатную работу без обязательных API-ключей. При указании `GROQ_API_KEY` автоматически подключается внешняя LLM для обработки сложных нетривиальных формулировок.

2. **Гибридный поиск (Hybrid Search)**:
   Для реализации требования «поиск ранее созданных записей без точного совпадения» скомбинированы:
   - Полнотекстовый поиск SQLite FTS5 с префиксным сопоставлением токенов.
   - Морфологический стемминг русского языка.
   - Кластеры синонимов («договор» ↔ «контракт» ↔ «соглашение» ↔ «акт»; «встреча» ↔ «созвон» ↔ «митинг» ↔ «планёрка»).

3. **Минималистичный дизайн**:
   Интерфейс выполнен в строгом монохромном стиле (Black & White) с точечной функциональной цветовой индикацией (красный — запись и конфликты, синий — встречи, зеленый — выполненные задачи). Отсутствуют лишние градиенты и визуальный шум.

4. **Анализ конфликтов**:
   Система проверяет совпадение по дате и времени для встреч как при диалоговом вводе, так и при ручном создании в модальном окне.

## Что можно улучшить при наличии дополнительного времени

1. **Векторные эмбеддинги**:
   Интеграция локальной модели эмбеддингов (например, `rubert-tiny2` или `all-MiniLM-L6-v2`) с сохранением векторов в SQLite через расширение `sqlite-vec`.
2. **Двусторонняя синхронизация по CalDAV**:
   Прямая интеграция с Google Calendar и Яндекс.Календарем для фоновой синхронизации изменений.
3. **Повторяющиеся события (Recurrence Rules)**:
   Поддержка правил повторения по стандарту RFC 5545 («каждый понедельник в 10:00»).
4. **Многопользовательский режим**:
   JWT-аутентификация с изоляцией расписаний разных пользователей.
